# jasoseo-panel

한국 공채 자기소개서를 일곱 명의 심사위원이 떨어뜨리려고 읽고, 문단마다 무엇을 왜 고칠지 알려주는 Claude Code 스킬입니다. 본문을 대신 써 주지 않습니다. 많은 회사가 지원서를 본인이 직접 쓰라고 요구하고, 서류 단계에서 AI 작성 여부를 검사하기 때문입니다.

## 심사위원

1. **AI 서류 평가.** 사람이 읽기 전에 거르는 단계입니다. 문항 의도, 공고 정렬, 다른 회사에 그대로 낼 수 있는 문장, AI가 쓴 티, 글자 수를 봅니다.
2. **인사팀 서류 담당자.** 면접에 부를지 정하고, 소제목과 첫 문장에서 무엇이 판단을 갈랐는지 씁니다.
3. **독립 리뷰어 다섯.** 서로의 의견을 보지 않고 각자 합격, 보류, 탈락을 줍니다. 현업 팀장, 같은 공채 경쟁자, 임원, 하루 수백 장 보는 인사 담당자, 함께 일할 선배입니다.

일곱 명의 지적을 합쳐 심각한 순서로 정리하고, 덩어리마다 문제, 방향, 소제목과 첫 문장 예시를 줍니다. 필요한 사실이 없으면 지어내지 않고 `[확인 필요: ...]`로 남깁니다. 고친 본을 다시 주면 AI 서류 평가만 다시 돌려 전후를 비교합니다.

결과는 실행한 폴더의 `.jasoseo-panel/<날짜>-<회사>/PANEL.md`에 저장됩니다.

## 설치

`skills/jasoseo-panel` 폴더를 `~/.claude/skills/`에 복사하고 Claude Code 세션을 새로 엽니다.

```bash
git clone https://github.com/Mm-767/jasoseo-panel.git
cp -r jasoseo-panel/skills/jasoseo-panel ~/.claude/skills/
```

## 사용

```
/jasoseo-panel ~/Documents/자소서.md  현대오토에버 SW개발 신입
```

문항 원문과 글자 수 제한, 공고(담당 업무, 자격요건, 우대사항, 인재상)를 같이 주면 가장 정확합니다. 이력서나 경력기술서도 같이 주면 자소서에 빠진 본인 몫과 결과를 거기서 찾아 수정 방향이 구체적이 됩니다. 빠진 것이 있으면 한 번 묻고 진행합니다. 한 번 실행하면 서브에이전트를 일곱 번 호출하므로 Claude 플랜 사용량이 꽤 듭니다.

자동 모드(auto mode)에서는 권한 검사가 서브에이전트 실행을 드물게 거부할 수 있습니다. 거부되면 같은 호출을 다시 보내지 않고, 메인 모델이 다른 결과를 읽기 전에 그 역할을 대신 맡아 "메인 모델 대행"으로 표시합니다.

설문은 조사 시기와 대상(신입·경력)이 서로 다릅니다. 오래된 조사도 최근 자료와 결론이 같아서 함께 남겨 두었습니다.

자소서 자체가 줄어드는 흐름도 있습니다. 구직자 93%가 자소서에 AI를 써 봤고 58%가 자소서 전형 폐지에 찬성했습니다([세계일보, 진학사 캐치 1,008명 설문, 2026-09](https://www.segye.com/newsView/20260929504093)). SK하이닉스는 2026년 하반기 신입 채용에서 자소서를 없애고 AI 활용 역량과 직무 전문성을 묻는 서식으로 바꿨습니다([링커리어](https://linkareer.com/stem-community/stem-employment/6313286)). 이런 서식도 "AI로 실제 문제를 해결한 경험", "근거와 수치가 있는 경험"을 묻기 때문에, 문항형 서식이라면 이 스킬의 기준 대부분을 그대로 쓸 수 있다고 봅니다. AI 작성 판정은 언어 모델의 판단이며 실제 탐지기 결과가 아닙니다. 이 스킬은 두 번째 의견일 뿐이고 서류 합격을 보장하지 않습니다.
